# Правила тестирования

Тестирование реализовано внутри приложения `learning` и связано с конкретным курсом и персональным назначением.

## Попытка

- запускать тест может только назначенный сотрудник;
- набор вопросов выбирается при старте и фиксируется в попытке;
- незавершённая попытка возвращается повторно вместо создания дубля;
- число попыток ограничивается минимумом настроек курса и теста;
- после превышения `time_limit_minutes` попытка получает статус `EXPIRED`;
- пустой обязательный тест отправить нельзя.

Правильность вариантов не передаётся в публичном сериализаторе вопросов.

## Проверка

Автоматически проверяются `SINGLE_CHOICE`, `MULTIPLE_CHOICE`, `TRUE_FALSE`, `NUMBER` и `IMAGE_CHOICE`. Для выбора требуется точное совпадение множества вариантов. Числовой эталон хранится в `match_key` правильного варианта.

`TEXT`, `CASE_STUDY` и вопросы с `manual_review_required` переводят попытку в `WAITING_REVIEW`. Руководитель выставляет баллы каждому открытому ответу; завершить проверку до оценки всех таких ответов нельзя.

## Результат

Процент рассчитывается как сумма полученных баллов к максимальной сумме вопросов попытки. Успешный результат завершает назначение. Неуспешный результат допускает новую попытку, а после исчерпания лимита переводит назначение в `FAILED`.

Если у курса включён сертификат, успешный результат создаёт сертификат с уникальными номером и кодом проверки. Срок рассчитывается по `certificate_validity_days`.

## API

- `/api/v1/learning/assessments/{id}/start/`;
- `/api/v1/learning/attempts/{id}/submit/`;
- `/api/v1/learning/attempts/{id}/review/`;
- `/api/v1/learning/attempts/my/`;
- `/api/v1/learning/certificates/my/`.

# Конструктор чек-листов задач

## Упрощение 15.10.2026 — локально/staging

Новый интерфейс оставляет название чек-листа и описание по значку вопроса
в круге. В редакторе описание редактируется в том же небольшом popup;
в библиотеке, предпросмотре и задаче оно читается только по нажатию.
Popup закрывается кликом снаружи и Escape. При пустом описании значок
в режиме чтения отсутствует; в редакторе доступен для добавления описания.

Новые пункты — только название и галочка. Из конструктора убраны раздел,
тип ответа, подсказка, обязательность, варианты и границы; новые строки
создаются как required checkbox. Скрытые параметры уже существующих пунктов
сохраняются при редактировании, автоматически не конвертируются. В задаче
скрыты подсказки/разделы/обязательность/даты/комментарии/дублирующие статусы
и прогресс. Галочка сохраняется сразу; снятие вызывает uncomplete с version.
Во время запроса контроль отключён, ошибка возвращает прежнее состояние.
Для старых typed items сохранён соответствующий ввод и прежние ответы:
текст/число/Да-Нет/варианты не превращаются в boolean и не теряются.
Права прохождения/управления и ограничения завершения задачи сохранены.

TaskChecklist.description — копия описания на момент прикрепления шаблона;
дальнейшая правка шаблона её не меняет. Аддитивная миграция
`0012_checklist_description` восстанавливает описания прежних экземпляров
только при совпадении source_template_version с текущей версией шаблона.
Для старой несовпадающей/неизвестной версии описание остаётся пустым:
исторический текст не подменяется новым. Ответы/UUID/пункты не меняются.

Проверки: PostgreSQL **26/26 PASS**, включая миграцию и независимость копий
описания; browser **12/12 PASS**, дополнительно toggle/uncheck **1/1** и
финальная mobile layout **2/2**; TypeScript/Vite, check/drift/diff PASS.
Миграция применена только к synthetic localhost staging. Production не менялся,
commit/push не выполнялись. Предыдущая доработка прямого выбора согласующего
и отложенные Telegram-файлы сохранены.

## Пользовательский путь

Раздел «Работа → Чек-листы» (`/checklists`; прежняя ссылка `/#checklists`
также открывает конструктор). Пользователь с `checklist_template.manage`
создаёт шаблон, задаёт название и описание, разделы, порядок пунктов, подсказки
и обязательность. Доступны шесть типов ответа: отметка «Выполнено», Да/Нет,
текст, число с необязательными границами, один вариант, несколько вариантов.
Есть предпросмотр, копирование и архивирование снятием флага доступности.
Новые права автоматически не выдаются; администратор назначает существующие
permissions через текущую систему ролей.

В карточке задачи пользователь с `task.checklist_manage` прикрепляет активный
шаблон. Название и пункты копируются, включая разделы, типы, варианты, границы и
номер версии. Новая версия шаблона не переписывает выданные чек-листы.
Архивирование запрещает новые прикрепления, но сохраняет имеющиеся результаты.

Пользователь с `task.checklist_complete` отвечает на пункты и оставляет
комментарии. Ответы сохраняются по пунктам с исполнителем и временем.
Да/Нет принимает и отрицательный ответ, число принимает ноль; это заполненные
ответы, автоматических нарушений/корректирующих задач в этом выпуске нет.
После сохранения ответ можно сбросить и ввести заново. При обязательных
незаполненных пунктах штатное завершение задачи запрещено. На приёмке,
в завершённой и отменённой задаче чек-листы доступны только для чтения.
Удаление из задачи мягкое, строки и ответы сохраняются для истории.

## Архитектура и совместимость

Расширены существующие UUID-модели `work_tasks.ChecklistTemplate`,
`ChecklistTemplateItem`, `TaskChecklist`, `TaskChecklistItem`. Legacy
`checklists`/`tasks` и их данные не изменялись и не используются для новых
шаблонов. Старая форма legacy-прохождения заменена в навигации конструктором;
существующие legacy API и результаты сохранены.

Миграция `work_tasks/0009_checklist_builder` только добавляет поля. Старые
пункты остаются отметками выполнения; ранее сохранённый `is_completed`
сохраняет смысл, даже если нового answer ещё нет. Миграция применена в production 14.10.2026. Планирование существующих шаблонов задач продолжает
использовать тот же `ChecklistService.from_template` и получает копии новых полей.

Использованы прежние Permissions/Audit/Outbox и проверка видимости задачи.
Изменение шаблона и замена пунктов атомарны. PATCH шаблона требует version;
устаревшая версия возвращает 409. UI передаёт version каждого ответа; конфликт
также возвращает 409. Старые клиенты с checkbox могут работать без version.
Операции над чек-листом блокируют строку Task, согласованно с завершением задачи.
Нельзя изменять схему отвеченного пункта до сброса ответа.

## API

- `/api/internal/v1/checklist-templates/` — список и создание;
- `/checklist-templates/capabilities/` — доступные возможности;
- PATCH `/checklist-templates/{id}/` — редактор, version и полная замена items;
- POST `/tasks/{id}/checklists/from-template/` — прикрепление;
- POST `/tasks/{id}/checklists/{cid}/items/{iid}/complete/` — answer, comment,
  version; `/uncomplete/` сбрасывает ответ;
- прежние ручные чек-листы и мягкое удаление сохранены.

Библиотека общая: просмотр активных шаблонов доступен с
`checklist_template.view`, `.manage` либо `task.checklist_manage`.
Неактивные шаблоны отображаются только управляющему библиотекой.
Видимость и прохождение экземпляра определяются правами конкретной задачи.

## Компоновка карточки задачи (локальная доработка 14.10.2026)

Пункты отображаются нумерованным списком с прогрессом. При наличии прикреплённого
чек-листа выбор нового шаблона свёрнут. Необязательные комментарии раскрываются
отдельно; сохранённые ответы и комментарии читаются как текст, с временем ответа
и действием «Изменить ответ». Версии продолжают передаваться прежним API.
Desktop/mobile browser-проверки включают все шесть типов в одном чек-листе.

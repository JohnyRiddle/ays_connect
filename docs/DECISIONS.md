# Подтверждённые решения

Полный исторический список ADR находится в корневом `DECISIONS.md`. Этот файл фиксирует актуальные решения, важные для продолжения production-разработки.

## Модульный монолит

Django-приложения отражают предметные границы, но разворачиваются единым backend. Это сохраняет общие транзакции и не вводит микросервисы без подтверждённой необходимости.

## Production и legacy Tasks разделены

Каноническая production-модель задач находится в `work_tasks.models.Task`. Legacy-приложение `tasks` сохраняется ради совместимости и не должно становиться источником новых production-связей.

## Общие People, Organization и Access Control

Новые домены переиспользуют production-сущности Employee, LegalEntity, OrgUnit, Location, FunctionalGroup и AssignmentTarget. Права проверяются сервером через общий permissions-контур.

## Audit и transactional Outbox

Значимые изменения фиксируются в неизменяемом Audit и публикуют integration-relevant события в Outbox в той же транзакции.

## Service Request schema snapshot

Администратор редактирует draft динамической формы. Публикация создаёт неизменяемую `RequestTypeSchemaVersion`; будущая Request должна хранить ссылку на конкретную версию, чтобы исторические заявки не менялись вместе с live-конфигурацией.

## Безопасность репозитория

Секреты поступают через локальные `.env`/окружение. В Git хранятся только example-файлы без production-значений. Commit и push выполняются только по явному запросу пользователя.

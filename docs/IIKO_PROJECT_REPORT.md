# iikoCard — итог работ от ТЗ до серверной версии

Дата фиксации: 11.09.2026. Сервер: https://ays-connect.ru/iiko-cards.

## Реализовано

1. Подключён iiko Cloud для Шерегеша / «Восточка / RMS 6». Проверены авторизация,
   организации, категории, программы, чтение карты. Реквизиты вынесены из репозитория.
2. По пользовательской тестовой карте подготовлен эталон. Создана отдельная страница
   с вкладками создания и проверки, полным номером карты, ФИО и локацией Шерегеш.
3. Добавлены справочники: подразделения, юридические лица, тип карты и согласование.
   Значения связаны с категориями iiko; проверка показывает сущности, категории,
   владельца, все его карты, комментарий и кошельки.
4. Создание выполняется по свободному номеру/треку без заранее переданного ID гостя.
   ID берётся из ответа iiko; затем назначаются четыре категории и проверяется результат.
5. Предупреждение о совпадении имени/фамилии учитывает отсутствие/различие отчества.
   Покрытие ограничено ранее наблюдавшимися гостями AYS Connect, о чём сообщает форма.
6. Занятый номер переоформляется через подтверждённое логическое удаление прежнего
   гостя методом delete_customers. Форма показывает все его карты и балансы.
   Создание нового гостя начинается только после подтверждения удаления и освобождения
   номера/треков. Балансы и история прежнего гостя не переносятся.
7. Необязательный многострочный комментарий до 2000 символов связан с полем comment
   гостя iikoCard. Комментарий общий для карт этого гостя и показывается при проверке.
8. После создания автоматически пополняется кошелёк AYS Sheregesh. Для питания
   начальная сумма 10000 ₽, допустимо 0.01–10000 ₽. Для депозитных и партнёрских карт
   сумма обязательна; ограничение питания к ним не применяется. Проверка суммы есть
   в форме и API. Успех операции требует подтверждения начисления чтением баланса.
9. Добавлены отдельные права view/create/delete_guest/topup, Audit/Outbox, квитанции,
   резерв номера, подпись подтверждения и защита от повторной записи. Изменение
   данных делает прежнее подтверждение недействительным.
10. Диагностика хранит этап, HTTP, время, метод, выбранные поля ошибки и correlationId,
    если он возвращён. Реквизиты подключения и переданные данные формы скрываются;
    полные ответы/запросы и пароли не записываются в журнал.

## Исправления по пользовательским тестам

- Случайный ID в create_or_update приводил к поиску несуществующего гостя; создание
  исправлено на запрос без ID и сохранение UUID, возвращённого iiko.
- Снятие единственной карты анонимного гостя запрещено iiko. По уточнению пользователя
  механизм заменён удалением гостя целиком с новым явным подтверждением.
- Неопределённые попытки остановлены; локальные резервы снимались вручную только
  после чтения и сверки прежней регистрации. История попыток сохранена.
- Исправлено отображение UUID-заготовки как реального гостя до подтверждения создания.
- Добавлен серверный предел 10000 ₽ для карты питания после уточнения регламента.

## Проверки и ограничения

- Основной серверный релиз: 426/426 тестов PostgreSQL и frontend build прошли.
- Исправление лимита питания: 102/102 теста iiko на SQLite и серверном PostgreSQL.
- Проверены HTTPS health, страницы, JWT-каталог, реальное чтение карты и отклонение
  10000.01 ₽ на prepare/create без создания операции.
- При выкладке и smoke-проверках внешние создания/удаления/пополнения не выполнялись.
  Реальные сценарии записи предназначены для пользовательского тестирования.
- У wallet/topup нет idempotency key. При timeout или несовпадении баланса —
  needs_review, без автоматического повтора или отката внешней операции.
- Backend работает одним worker; масштабирование требует распределённого limiter.
- Этот checkpoint сохраняет локальную ветку от e03731c, включая ранее накопленные
  изменения learning/knowledge. Их известное падение полного локального gate — UUID
  employee_id в learning.test_integrations — не относится к выложенному пакету iiko.
  В origin/main уже есть более новые изменения: перенос checkpoint туда требует
  отдельной интеграции, нельзя заменять main этим снимком или применять force-push.

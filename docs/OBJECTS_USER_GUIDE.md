# Объекты — руководство локального кандидата

Откройте `/objects` (старый `/#objects` также поддерживается). Реестр сохраняет поиск, географию, тип, статус, архив, юрлицо, ответственного и страницу в URL. Отображаются только доступные карточки; пустой результат не означает отсутствия объектов у других пользователей.

## Создание и карточка

1. При наличии права нажмите «Добавить объект». Desktop открывает правую панель, mobile — полноэкранную форму; Escape закрывает её, Tab остаётся внутри.
2. Заполните название, бизнес-тип и видимый часовой пояс. По умолчанию Asia/Novosibirsk; при выборе географии с валидной timezone она предзаполняется. Географию можно не указывать — фиктивный регион не создаётся.
3. По необходимости выберите адрес, основное юрлицо/подразделение, контакты, график, описание и ответственных. Ограниченный scope требует явного доступного контекста. Подразделение должно соответствовать выбранному юрлицу.
4. Нажмите «Создать объект». При вероятном видимом дубле подтвердите продолжение. После сетевого сбоя повторная отправка сохраняет ключ запроса, поля и уже созданную карточку, не делает дубль.
5. Откроется карточка в «Подготовке» с OBJ-кодом; кнопка «Добавить зоны» создаёт их отдельными действиями. Ошибка зоны не отменяет объект. Вложенную зону можно добавить из её карточки.

«Редактировать» меняет сведения, «Назначить ответственного» выбирает управляющего/технического Employee. «Не указано» завершает текущий период; история остаётся. Назначение не выдаёт сотруднику доступ. Увольнение завершает ответственность, реактивация её не возвращает. «Переместить» проверяет оба контекста, циклы и используемые связи; зона со связями не переносится в другой объект.

## Состояния и связанные данные

«Начать работу» требует местоположения, юрлица и управляющего. Сезонное закрытие/возобновление сохраняет кадровые назначения и задачи. Окончательное закрытие требует причины. Архивирование объекта доступно после него и только без действующих связей/незавершённых задач. Общий blocker не раскрывает чужие сведения. Восстановление из архива сохраняет окончательное закрытие; «Возобновить в подготовке» — отдельное действие. Физического удаления нет.

Вкладки загружаются при открытии: зоны, ответственность, сотрудники из EmployeeAssignment, задачи, заявки, прямые проекты, участие через задачи, история. Права каждого домена сохраняются. «Создать задачу»/«Создать заявку» открывают существующую форму с Location объекта; сервер проверяет выбор повторно.

При конфликте версии введённые поля остаются. Нажмите «Обновить карточку», сопоставьте свежие изменения и повторите сохранение. При отзыве прав команда может быть запрещена даже после ранее успешного создания.

## Синтетический стенд

Только локально: UI `http://localhost:13031/objects`, API `http://localhost:18081`; отдельная PostgreSQL без production connections. Fixture: `deployment/objects-staging/prepare_synthetic.py`, проверяет PostgreSQL и имя выделенной БД `objects`.

Оператор `objects@synthetic.test`; отрицательная персона `objects-denied@synthetic.test`. Пароль обеих исключительно синтетический: `SyntheticObjectsOnly1!`. Эти значения не являются рабочими credentials, не подходят для production. Demo Employees явно is_demo; все названия маркированы синтетическими. Никаких реальных grants/Facility fixture не создаёт.

Compose для воспроизведения: `docker compose -p ays-objects-synthetic -f deployment/objects-staging/compose.yml up --build`. Он выполняет migrate/fixture **только в своей новой синтетической БД**, API/UI привязаны к loopback; не использовать этот startup для O0 аудита или рабочей БД. В данной сессии запускался эквивалентный отдельный Docker stack, сам Compose проверен `config --quiet`. Не запускайте одновременно оба на одинаковых портах.

Для больших каталогов UI пока ограничивает выбор Employee первыми 200 и move первой страницей; операция через API поддерживает видимые UUID/search/page. Production данные и реальное mapping ещё не проверены: [O0](OBJECTS_O0_ACCEPTANCE.md).

Финальный synthetic gate 08.10.2026 также использует `objects-editor@synthetic.test` с тем же исключительно синтетическим паролем: view/edit без организации/HR. Скрытые организационные связи сохраняются при редактировании контактов. PATCH отправляет только изменённые поля; после conflict refresh неизменённые поля чужой версии не перезаписываются.

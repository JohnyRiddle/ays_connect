# Projects — руководство пользователя

Создайте проект в разделе «Проекты»: укажите название, цель, ожидаемый результат, руководителя, при необходимости заказчика и подразделение, плановые даты. После создания добавьте участников и этапы, назначьте ответственных и контрольные точки. Проект начинается явной командой «Начать». Архив — отдельное действие после завершения работы.

Задачи проекта являются обычными задачами Work. В карточке проекта создайте задачу напрямую или из шаблона Work либо найдите существующую задачу и привяжите её. Назначение этапа и отвязка выполняются отдельными командами. Участник проекта видит только те задачи, на которые у него есть права Work; проектное участие само по себе доступа к Work не даёт. Задачу можно открыть в Work для её обычных переходов и обязательной приёмки.

В деталях проекта доступны список, доска и временная шкала, прогресс, просрочки, обязательные точки, комментарии с упоминаниями и защищённые вложения. Перенос карточки на доске запускает существующую разрешённую команду Work с проверками прав и приёмки; неподдерживаемый переход предлагает открыть карточку Work. Перед завершением выполните приёмку всех связанных задач Work и подтвердите обязательные контрольные точки. `REVIEW` не считается завершением. Если Work-задачу повторно открывают после завершения проекта, проект автоматически возвращается в ACTIVE с историей и уведомлением руководителя. Архивный или отменённый проект сначала нужно восстановить либо разрешённо отвязать задачу.

Отмена и ON_HOLD проекта не меняют статусы Work-задач. Удаление непустого этапа запрещено. Повторное открытие проекта и подтверждённой точки требует явного действия с причиной. Канонического механизма зависимостей Work-задач сейчас нет; метрика блокировок по зависимостям не отображается.

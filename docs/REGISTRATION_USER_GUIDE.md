# Регистрация AYS Connect — без писем

## Сотрудник

Нажмите «Зарегистрироваться» на странице входа. Укажите фамилию, имя, необязательное
отчество, обязательный email любого домена, объект и пароль с подтверждением.
Проверки адреса письмом нет. Заявка сразу «Ожидает согласования»; рабочий вход закрыт
до одобрения руководителем/администратором. Статус, причина отказа и отмена доступны
в этой вкладке/сессии. Сохраните доступ к ней; если статус недоступен, обратитесь к
согласующему. Письма о решении не отправляются, нажмите «Обновить статус».

Invite фиксирует объект/роль/scope/ответственность. Заполните данные и пароль; при
успешном принятии статус «Одобрена», можно войти сразу. Если адрес привязан к ссылке,
введите именно этот адрес: это совпадение, не подтверждение почтового ящика.
Used/expired/revoked ссылку перевыпускает руководитель. Ссылка и status capability
секретные, не публикуйте в общем чате. Старая confirmation ссылка больше не активирует.
Для существующего аккаунта используйте вход/штатный lifecycle, не саморегистрацию.

## Согласующий

Откройте «Сотрудники → Заявки на регистрацию». Новые самостоятельные заявки сразу
видны в разрешённых объектах. Проверьте ФИО/email/объект, явно выберите existing
Employee при необходимости, назначьте делегируемую роль/scope/ответственность и
одобрите. Для отказа обязательна причина; автор и решение сохраняются в аудите.
Email не подтверждён, поэтому внимательно проверяйте административное сопоставление.

Создайте invite: объект обязателен, email binding необязателен, default роль —
просмотр своего объекта/профиля, срок до 7 дней. Скопируйте одноразовую ссылку и
передайте сотруднику напрямую. Автоматической отправки нет. Reissue отзывает старую
ссылку. При returning сначала штатная People реактивация; старые grants не возвращаются.
Ответственность selected/all отделена от scope; all требует отдельного полномочия.
Employment, ответственность и роли показаны отдельно; primary changes сохраняют историю.

## Оператор

SMTP настройки для выпуска не требуются. Не включайте отправку старых registration
mail events: миграция и tombstone consumer переводят их в terminal failed без retry.
Старые object email_pending заявки отменяются с историей; руководитель оформляет
новую заявку/перевыпускает invite. Подтверждение email не восстанавливают обходом API.
Основные release gates: свежая восстановленная рабочая копия, сохранность grants,
миграции, scoped согласующие и делегация. Новые обычные аккаунты не получают доступ
к legacy разделам без утверждённого Location mapping.

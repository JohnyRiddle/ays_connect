# Регистрация AYS Connect

## Сотрудник

На странице входа нажмите «Зарегистрироваться». Введите фамилию, имя, необязательное
отчество, действующий email любого домена, объект и пароль с подтверждением.
Откройте ссылку подтверждения из письма. До решения доступны собственный статус,
resend и отмена; рабочие данные закрыты. После одобрения войдите с email/паролем.
При отказе отображается причина. Для существующего аккаунта используйте вход или
штатное восстановление; саморегистрация не возвращает уволенного сотрудника.

Invite уже фиксирует объект, роль, ответственность и scope. Заполните ФИО/email/пароль,
подтвердите email; дополнительное одобрение не требуется. При email binding используйте
именно адрес получателя. Used/expired/revoked ссылку должен перевыпустить руководитель.
Confirmation работает и при открытии ссылки в уже используемой вкладке.

Ссылка и status capability секретные; не отправляйте их в общий чат. Confirmation
в другой вкладке восстанавливает собственный status capability из подтверждённой почты.

## Руководитель

Откройте «Сотрудники → Заявки на регистрацию». Создайте invite: объект обязателен,
email необязателен, роль по умолчанию — просмотр объекта и своего профиля, срок 7 дней.
Если Employee уже существует, выберите его явно. ФИО не создаёт автоматическую связь.
Укажите access_locations и отдельно ответственность selected/all. Ответственность
прав не даёт; all требует отдельного полномочия. Скопируйте ссылку. При email/SMTP
письмо также отправляет consumer. Reissue аннулирует старую ссылку и её pending заявку.

Фильтруйте заявки по статусу и объекту. После email confirmation проверьте ФИО,
выберите роль/scope/ответственность и одобрите. Для отклонения обязательна причина.
Списки, карточки, counts и lookups ограничены вашей областью. Роль и объекты можно
делегировать только в пределах текущих полномочий.

Перед приглашением возвращающегося сотрудника выполните штатную People реактивацию.
Старые grants не восстанавливаются; privileged/legacy аккаунты возвращаются отдельно.
В Employee card трудоустройство, ответственность и роли/scopes показаны раздельно.
Основной объект меняется с историей primary, без изменения входа/должности/юрлица.
Назначение/отзыв выбранной роли сохраняет остальные назначения. All ответственность
включает новые действующие объекты, но не расширяет список доступа автоматически.

## Если письмо не пришло

Проверьте spam и статус; до confirmation доступен resend с rate limit. Оператор
проверяет mail events, accepted_recipients и codes. DELIVERY_OUTCOME_UNKNOWN нельзя
считать недоставкой и отправлять автоматически снова; нужен явный resend/reissue.
Receipt состояния Outbox не является доставкой. Пароли и ссылки не копируют в логи.

Новая минимальная роль открывает свой объект и собственный профиль. Legacy разделы
для новых обычных аккаунтов пока закрыты: их права нельзя выводить из Location
без отдельного утверждённого соответствия старых справочников.
